# HTML DOCS TO Learn

An Astro-based static site and document directory routing to local and imported HTML pages, with content managed via Supabase and automated GitHub Pages deployment.

For styling rules, typography, color tokens, and layout guidelines, see [DESIGN.md](DESIGN.md).

---

## Prerequisites

- **Node.js**: `>= 22.12.0`
- **npm**: `>= 10.0.0`
- **Supabase Account**: For managing dynamic content (about page details and `/tried` experiment entries) and image storage.

---

## Setup

1. **Clone repository & install dependencies**:
   ```bash
   git clone https://github.com/himanshu-systems/himanshu-systems.github.io.git
   cd himanshu-systems.github.io
   npm install
   ```

2. **Configure Environment Variables**:
   Ensure `.env` contains your Supabase project credentials (publishable key is safe to commit):
   ```env
   PUBLIC_SUPABASE_URL=https://<your-project>.supabase.co
   PUBLIC_SUPABASE_KEY=<your-publishable-key>
   ```

3. **Initialize Supabase**:
   Follow the step-by-step setup in [supabase/README.md](supabase/README.md):
   - Run `supabase/schema.sql` in the Supabase SQL Editor (creates `tried_entries` table, RLS, and seeds initial data).
   - Run `supabase/site_content.sql` (creates `site_content` table and seeds about page data).
   - Run `supabase/storage.sql` (creates `site-images` storage bucket and policies).
   - Create your admin user in Authentication and disable public sign-ups.
   - Configure Database Webhooks pointing to GitHub repository dispatches for instant rebuilds on content updates.

## Development Commands

| Command | Description |
|---|---|
| `npm run dev` | Runs `tools/prepare.mjs` and starts the Astro local development server at `http://localhost:4321/` |
| `npm run build` | Runs `tools/prepare.mjs` and compiles the static site into `dist/` |
| `npm run build:refresh` | Re-imports external pages and compiles a fresh production build |
| `npm run preview` | Serves the generated `dist/` folder locally to preview the production build |
| `npm run import` | Re-fetches all external page snapshots marked with `"mode": "import"` |
| `npm run add` | Interactive CLI helper to register a new local or external page into `pages.json` |
| `npm run check` | Runs Astro type and diagnostic checks |

## Project Structure

```
├── pages/              # Standalone local HTML documents
├── pages.json          # Registry defining routes, titles, tags, and types
├── public/             # Build output assets generated by prepare.mjs (gitignored)
├── static/             # Committed static assets (images, favicon) copied to public/ during build
├── src/
│   ├── components/     # Astro UI components (ThemeToggle, SocialIcon, FloatingShape, etc.)
│   ├── layouts/        # Page layouts (Doc.astro for prose, Frame.astro for embeds)
│   ├── lib/            # Utilities (Supabase client, buildCache, path helpers, filters)
│   ├── pages/          # Astro routes: / (about), /pages (directory), /tried, /admin
│   └── styles/         # Global design tokens and base styles (tokens.css)
├── supabase/           # SQL schemas, storage policies, and dashboard setup guides
└── tools/              # Node.js scripts for page preparation, import snapshots, and CLI registration
```

## Deployment & CI/CD

- **GitHub Pages**: The production site is deployed automatically using GitHub Actions (`.github/workflows/deploy.yml`).
- **Automatic Rebuilds on Content Edit**: Editing content or uploading photos via `/admin` updates Supabase, which triggers GitHub Actions via Database Webhooks (`repository_dispatch`).
- **Build-time Caching**: Supabase fetches during static site generation are cached locally in `.cache/` (via `src/lib/buildCache.ts`), ensuring builds succeed even during temporary network interruptions.
- **External Page Refresh**: `.github/workflows/refresh.yml` can be run manually or on a cron schedule to snapshot external pages and commit updates.
